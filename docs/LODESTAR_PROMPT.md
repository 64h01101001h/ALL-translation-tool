# MASTER PROMPT 10 — THE LODESTAR ENGINE
*(The tenth prompt, and the first written WITH the firm's installed
skills as its method rather than its afterthought. Nine engines asked:
is it correct, honest, sound, shippable, survivable? All nine shared
one blindspot-of-blindspots: they audited the tool against ITSELF —
its own promises, its own pins, its own registers. The Lodestar audits
the tool against the JOB IT WAS HIRED TO DO and the HUMANS WHO WILL DO
IT, using the formal frameworks the design wing carries: Norman's
conceptual models, Cooper's excise and posture, the Laws of UX,
journey-mapping, UX-writing review. Its second charge: BRAINSTORM —
skill-led, framework-grounded — the capabilities the tool wants next,
and build the flagship. The 1.0 RC freeze HOLDS: this engine works the
1.1 line on main; the nine signatures still gate 1.0.)*

## PART I — THE LODESTAR ITSELF

**§1. The job.** This tool exists so that a human reading ANY Tibetan
text has Geshe Michael's attested English, the corpus's evidence, and
the tradition's own voices AT THEIR ELBOW — and so the team's
judgments (rulings, glossaries, comments, catalogs) accumulate into a
permanent, honest record. Every finding and every feature is weighed
against THAT, not against feature-lists or engine-pride.

**§2. Skills govern method.** Each track names its governing skill(s)
and FOLLOWS them — brainstorming before creation, design-critique
frameworks for evaluation, journey-mapping for personas, TDD +
subagent execution for builds, requesting-code-review before merges,
verification-before-completion always. The Master UX Oversight
(§63/§53) and the CLAUDE.md honesty rules remain supreme over any
heuristic.

**§3. The blindspot ledger.** Every finding names the BLINDSPOT CLASS
it emerged from ("audited against itself, not the job", "built for
Adam's eye", "excise normalized as ritual", "model never taught") —
so Adam receives not just fixes but the ways of seeing he asked for.

## PART II — THE TRACKS

**L1 · The conceptual-model audit** *(don-norman-principles-audit,
design-critique)*. Norman: users act through the model the interface
teaches. The tool has a beautiful hidden model — a scholarly PIPELINE
(read → understand → draft → review → rule → publish) over a sacred
DATA HIERARCHY (HGM binding > evidence > reference > machine > AI).
Nothing on screen teaches either. Audit every surface for
model-teaching failures (mystery groups, unexplained tiers, invisible
pipelines); deliver the model MAP and the smallest set of changes that
make the tool self-explaining (group tooltips that state roles, a
one-screen "how this tool thinks" reachable from Welcome/Help,
pipeline position cues on panes).

**L2 · The excise hunt** *(design-critique's excise audit; Cooper)*.
Excise = work that serves the software, not the goal. Inventory it
ALL: every relaunch notice, every re-chosen folder, every per-session
password, every "set your name in Propose first", every quit-and-
reopen, every pane-hop a journey forces, every re-found term. Each
item: KILL (engineer it away), COLLAPSE (one act instead of three),
or JUSTIFY (a written reason the user would accept). The excise
minutes-per-week metric goes in the ledger.

**L3 · The other humans** *(journey-mapping, ux-research posture)*.
The tool was built under one expert eye. Walk three personas END TO
END on the RC: (a) the input-center cataloger — modest English,
first month; (b) the authority — time-poor, needs the queue to
respect minutes; (c) the student translator — knows Tibetan, not
this tool. Each journey: goals, steps, moments-of-confusion,
moments-of-delight, abandonment risks. Frictions file as findings
with persona names attached.

**L4 · The laws sweep** *(ux-designer references, design-systems)*.
Fitts (targets/distances on the band and card), Hick (choice
overload — 22 panes, 14 card layers), Miller/chunking (the card's
zone order and density), Jakob (does it behave like the apps users
already know — Word grammar held?), Tesler (complexity conservation:
what burden sits with the user that the software could carry?).
Component-consistency pass over the de-facto design system.

**L5 · The voice** *(design-critique's UX-writing review)*. Every
user-facing string audited for: parsability by a non-native reader,
instruction-before-jargon, consistency of the ritual vocabulary
(press/ruling/register/tier), error messages that give the NEXT ACT.
Honesty wording stays verbatim — clarity added AROUND it, never
inside it.

**L6 · THE FLAGSHIP** *(brainstorming → Adam's pick → the full firm
flow)*. Skill-led brainstorm, framework-grounded, of what the tool
WANTS next — seeded candidates (each named by the framework that
surfaced it):
1. **Translation Dossiers** (Norman: the object model users actually
   think in) — ONE first-class object binding a text + its draft +
   glossary + comments + teachings + links + progress, opened as a
   unit, resumed as a unit, shared as a unit. Today that identity is
   scattered across per-pane session crumbs.
2. **The Pipeline Map welcome** (L1's model, made a screen) — the
   tool teaches its own idea in one diagram, every group clickable.
3. **The Feedback Layer** (H1 at scale) — every band action answers
   in the status bar; silence becomes impossible.
4. **Focus Reading posture** (Cooper: sovereign apps deserve a
   reading mode) — chrome recedes, text and card remain.
5. **The Glossary Workbench** (excise: per-text glossaries exist but
   are click-buried) — a pane where a translator SEES and tends the
   text's growing glossary.
6. **Team Presence** (the many-hands model made visible) — who
   commented/ruled/staged what, lately, in one activity feed from
   the stores we already have.
Adam picks the flagship (recommendation will accompany the
brainstorm); it ships end-to-end: brainstorm → written plan →
plan-review → TDD → subagent execution where parallel → code-review
→ verification → announced press.

## PART III — DOCTRINE AND EXIT
**§10. Order:** L2 excise inventory (fast, immediately actionable) →
L1 model audit → L4 laws sweep → L5 voice → L3 personas (they
inherit all prior fixes) → L6 brainstorm + flagship. Findings fix as
they land (small) or batch (structural); presses announced; every
GUI change passes design-critique + accessibility-audit before Adam
sees it; batteries + constitution + visual + geometry gates at every
commit.
**§11. Exit:** every track's findings fixed/ruled with blindspot
classes named; the excise metric reduced and recorded; the model map
shipped; the flagship LIVE and pressed; ledger docs/LODESTAR.md
closes with the letter: what the tool now teaches, what it stopped
demanding, and what it became able to do that it couldn't before.
