## VII. EXTERNAL ROUTING — THE OPENROUTER QUESTION, THE MODEL ARENA, AND THE PINNED DECISION

*(Added 2026-09-23 at Adam's direction, after he researched OpenRouter and TypeSafe AI JEV himself and put the proposal to the audit. His facts were checked one by one; most stand. This section does not answer the question of whether to buy a gateway — it states what the audit must MEASURE before the question can be answered at all, and it forbids the shortcuts. Every third-party fact below carries its check date and expires at the next re-evaluation: a fact past its date is UNVERIFIED, not true. The roman numeral is provisional — set it to follow the last section in force.)*

**§VII.1 The doctrine. A gateway is a purchase, not an optimisation.** It buys model routing, provider failover, one bill, and — the single most valuable item on Adam's list for this project — per-request `cost`, `cached_tokens` and `cache_write_tokens` accounting, which is the only thing on that list that produces an artefact the provenance rules can bank. It does not buy accuracy. It does not buy caching this project has not yet earned. And it is not free: routing existing traffic through OpenRouter costs roughly 5–5.5% more than calling the provider directly (credit-purchase fee; BYOK 5% above a free tranche), which against a corrected base is $1,400–$1,600. Put that on the right side of the ledger. Nothing in this section closes by citing a vendor page. Each item closes on a measurement this repo can re-derive, or it is written UNVERIFIED and carried as such — never "fine".

**§VII.2 The base before the percentage.** No saving is quoted until the bill it is a share of has been re-derived in the same pass, on the same rung of the same ladder. The worked example is ours: **$44,086 is 6,172 × $7.1429 — the mandate remainder BEFORE the 2,099 exact duplicates are subtracted — and it was printed beside the 4,073-unique-segment scope.** The measured scope prices at 4,073 × $6.69 = **$27,248**, or × $7.14 = **$29,093**. Every percentage quoted against $44,086 is overstated by 1.52×. Re-derive the ladder in the pass rather than from this text: 8,961 (C01–C18) − 1,041 (C13, excluded) − 1,748 (landed) = 6,172 − 2,099 (exact duplicates) = 4,073. And state the BASIS of every token figure: 5,398,830 tokens per segment is tokens-moved INCLUDING cache reads; strip them and 248,612 + 104,580 + ~117 = 353,309, which is the quantity the earlier 322,727 and 651,499 figures measured. Both can be true. Neither may be set beside the other without saying which basis it is on. None of the three is re-derivable from this tree, which is this repo's oldest recorded failure shape — fix that before quoting them again.

**§VII.3 The harness boundary is declared before any vendor is named.** Classify every workload as HARNESS-RESIDENT or ORDINARY API CALL. A proposal that does not say which has not been read.

*Harness-resident.* `.claude/workflows/scripts/c05-align.js` (643 lines) **composes no requests.** It calls `agent()` and `parallel()`; the harness owns the tool loop, the bash sandbox, each agent's private directory, `SPEC_SCHEMA` validation, concurrency and retry. Adopting a gateway here is not a transport change — it is building an agent runtime. Name what is lost before pricing it: the mandatory pre-flight loop against `tools/gen_alignment_page.py`, a free, local, deterministic oracle that refuses any span not verbatim in the spine. The loop is INSTRUCTED (`docs/alignment_briefs/PROPOSE_BRIEF.md:86`, `RECONCILE_BRIEF.md:108`, "PRE-FLIGHT — MANDATORY … FIX THE SPEC AND RUN IT AGAIN until it exits 0"); what is not instructed is the COUNT — roughly 4.7 runs per propose agent and 3.7 per reconcile is a repair loop CONVERGING, and the convergence is the method. In the harness each iteration costs a local tool call. In a rewritten API client each becomes a full round-trip re-sending the whole growing context — the exact 98.1%-input-side shape this audit exists to cure. The rewrite makes the measured defect worse. Note also that the Decisions API cannot be either agent in this campaign: JEV cannot generate text, produce reasoning chains, or make tool calls, while propose decomposes a segment into 25–60 spans and reconcile writes an argument and iterates a generator.

*Ordinary API calls, verified by grep.* Four single-shot POSTs to `https://api.anthropic.com/v1/messages`: `tools/build_ai_glossary.py:64`, `app/analyze_cli.cpp:52`, `app/main.cpp:4101`, `app/main.cpp:29383`. Three carry `anthropic-beta: server-side-fallback-2026-07-01` (`analyze_cli.cpp:55`, `main.cpp:4104`, `main.cpp:29386`). For any redirect, **beta-header passthrough is MEASURED, not assumed** — a gateway that drops it still returns 200, and the refusal fallback simply stops existing with no error and no log line. Two of those sites are in the SHIPPED app and carry the user's own text against `docs/PRIVACY.md:86` ("the deterministic core stays offline") and `:100` ("Nothing is uploaded … There is no server that receives your work"). Changing what they send is a disclosure and licensing decision, checked against that document before it is checked against price. `build_ai_glossary.py` — build-time, local, Adam's key — is the only low-stakes place to measure gateway latency, beta passthrough, usage-accounting fidelity and ZDR behaviour, and it is where the measurement starts.

**§VII.4 Free levers before paid ones — and the cache is a free lever currently failing.** Before any external routing is assessed, measure `cache_read_input_tokens`, `cache_creation_input_tokens` and `input_tokens` for a real fan-out batch and answer one question: do N parallel agents sharing a byte-identical prefix read each other's cache entry? The known answer is no, and the mechanism is not the one the audit brief assumed: the cache is a workspace-scoped PREFIX cache, not a conversation-scoped one, and an entry becomes readable only once the first response BEGINS STREAMING — so `parallel()` firing every propose agent at once has all of them pay write price. The fix is ours to make: fire one request, await its first streamed token, fire the remaining N−1, and set a cache breakpoint at the end of the shared head (`proposeCommon()` already emits the byte-identical brief, supplement and course context before the per-segment blocks). **No gateway does this for you.** `session_id` pins you to the same PROVIDER; it does not create a cache entry and does not change prefix semantics. A pipeline that has not done this has not earned the right to discuss vendors.

**§VII.5 Route what you already ruled you would route.** Verified in this pass: both briefs carry "MODEL POLICY (Adam, 2026-09-01): PROPOSE agents run on Claude Opus 5. RECONCILE and REFUTE agents run on Claude Fable 5.1, high effort" — and `c05-align.js` requests `model: 'opus'` at all three call sites (lines 521, 560, 614). The project's only existing routing policy is not implemented by the harness that runs it, and every cost figure in the audit was measured under the harness's behaviour rather than the policy's. Worse for the argument being made: `'opus'` is itself an unpinned alias inside our own tree, which is precisely what §VII.10 forbids externally. Implement the routing already ruled, or rescind it in writing, before buying routing from anyone.

**§VII.6 The prerequisite — no arena, no threshold, no tier without a human yardstick.** Verified at source: `data/alignment/audit_verdicts_20260904.json` names its own labellers in its `models` key — `first_read: claude-opus-5`, `second_reader: claude-fable-5-1`, `skeptics: claude-fable-5-1`; n=100; `confirmed_total` 19; Wilson 95% [0.125, 0.278]; item keys `eng, final, first_read, headword, i, ref, second_reader, skeptics, stands` — **no adjudicator, reviewer, human or `verified_by` field anywhere in the file.** Grading a candidate against it measures agreement with Claude, and with the same models that do the proposing and reconciling. That is not a risk to manage; it is the current state of the instrument.

Therefore, until a sealed human set exists: **no accuracy claim, no confidence threshold, no routing tier, no model arena, and no per-question calibration fit may be built or quoted.** Adam's .98 / .92 / .75 tiers are claims about the probability of being right and have nothing to be measured against; independent evaluation of JEV also puts all three inside a region where accuracy above threshold is flat from 0.50 to 0.95 and only jumps at 0.99, with expected calibration error 0.107 and choice/score answers overconfident. What IS permitted now, today, with nothing leaving the machine: (a) the full provenance record of §VII.10; (b) SHADOW MODE against decisions already landed, recording DISAGREEMENT RATE — measurable without ground truth and never written down as accuracy; (c) a disagreement-triage queue that turns a machine signal into human-adjudication throughput, never an automated edit; (d) FALSIFICATION gates, which this repo's history shows hold here where correctness gates do not; (e) the closed-option gate of §VII.11.

*The minimum viable human-labelled set, with its arithmetic and its limits.* The currency is adjudicated DEFECTS, not spans. At the measured 19% base rate, estimating a checker's precision to ±5 points at p≈0.90 needs ~138 positive-class items ≈ **730 randomly drawn spans** — the honest unstratified number. The stratified minimum to put to Adam is **400**: 200 drawn at RANDOM from the landed bank (this stratum, and only this stratum, gives an honest base rate) and 200 drawn from the pool the free detector already flags (power on the positive class), reweighted to recover population estimates. That yields ~38 random-stratum defects — enough to answer "is this checker better than the free detector we already have, yes or no" to a few points, and **not enough to rank five models**. Say so before it is built, not after. Four non-negotiable design rules, three of which the existing file breaks: (1) a NAMED HUMAN ADJUDICATOR recorded per item; (2) the adjudicator must not see the machine verdict — the present file is a `first_read → second_reader → skeptics` chain, anchored by construction; labels first, verdicts revealed after; (3) a 15% DOUBLE-ADJUDICATED overlap so inter-rater agreement is itself measured; (4) the set is drawn and SEALED before any candidate touches it, and no model that will be graded on it helps select it. Tempering context that must appear beside any proposal to add a probabilistic checker: the free detector already runs at precision 1.00 / recall 0.58, and `data/alignment/span_head_allow.json` holds 38 adjudicated licensors (10 in `pages_c04`, 28 in `pages_c05` — counted) against roughly 2,256 spans the gate flags. That is 1.7% worked. **The bottleneck is ADJUDICATION, not DETECTION.**

**§VII.7 The capability tiers — classified by what a model can do here, not by price.** A tier is not a price band.
- **T0 · DETERMINISTIC AND LOCAL** — `gen_alignment_page.py`, the gates, the spine, the engine ports. Tried first, always. Anything a T0 oracle can decide never goes to a model, and the audit must measure what share of each tier's traffic a T0 could have answered.
- **T1 · CLOSED-SET CLASSIFIER** (the JEV class) — chooses among options supplied to it; cannot generate text, reason, or call tools. Eligible only for gated, closed-option decisions under §VII.11. If it is ever used here the unit of work is the SEGMENT, never the span: latency is ~430ms fixed regardless of workload, and 800 typed judgments in a single call measured 985ms for $0.00075, so one segment's 25–60 spans is one call. Ask narrow questions, never one broad one — decomposition beat a single question by 32 points on the one independent benchmark that tested it. Carry these UNVERIFIED items with it, all of them load-bearing: **no published evidence of any Tibetan, Wylie, EWTS, ACIP or Devanagari capability whatsoever** (the vendor makes no multilingual claim; the most rigorous independent evaluation ran no multilingual testing; the circulating "51 languages" figure traces to an unattributed card at a 15% floor and names no Tibetan); the Decisions endpoint is tagged ALPHA; prompt caching on it is undocumented — price it at 1.0×, not 0.1–0.5×; and the 50% batch discount does not reach it.
- **T2 · MIDRANGE GENERATIVE WITH TOOLS** — a candidate for the propose half only, and only after T3 has set the ceiling on the same sealed items.
- **T3 · FRONTIER WITH TOOLS** — the incumbent at every judgment step where a claim leaves the building.

**§VII.8 The arena, and its metric.** When — and only when — the sealed set exists, run every candidate over OpenRouter's catalogue and the direct providers on the SAME sealed items, the same prompts, the same schema, and the same generator gate. **The ranking metric is COST PER CORRECT SCHOLARLY DECISION AT A REQUIRED QUALITY THRESHOLD, not accuracy and not price.** Dollars come from the provider's own returned usage accounting, never from an estimate; correct decisions are those that survive both the deterministic gate AND the human yardstick; and a candidate that fails the quality threshold does not receive a cost score — it is excluded, because the binding constraint here is a false correspondence banked, not a dollar spent. Report alongside it, for every candidate: wall-clock per segment, round-trips per segment, repair iterations to `EXIT=0`, defect rate broken out by the measured classes (OVER_CAPTURE, UNDER_CAPTURE, WRONG_MAPPING), and a Wilson interval on every rate. **A difference inside overlapping intervals is not a result.** The routing hierarchy is an OUTPUT of this run and is written down only after it, with its intervals attached — no model is named in the design, and "we will use X for the cheap half" is not a finding until the arena says so.

**§VII.9 Re-evaluation, and the incumbent rule.** Re-run quarterly, and on any of: a new candidate, a price change, a dated build moving under a pinned name, or a gateway schema change. **Nothing replaces an incumbent unless it beats that incumbent on THIS project's own sealed benchmark, at the required quality threshold, with non-overlapping intervals, on the same items.** Vendor benchmarks, leaderboards, arena ELOs and community spend share are inadmissible. A cheaper model that merely ties does not win the judgment step: the reconcile pass is where a claim leaves the building, and a dashboard that makes the propose pass look expensive will argue against that policy every day and will be wrong every day.

**And the Auto Router is excluded, standing — Adam reached this himself and he is right.** It classifies each prompt into one of ~30 task types and then ranks candidates by REAL-WORLD SPEND SHARE across the OpenRouter community over a trailing 7-day window. The vendor presents this as a feature: the router follows the market within days, with no retraining. For a classical-Tibetan philology corpus it is an uncontrolled input — the model serving our segments can change because unrelated developers changed what they buy for "code:debugging" — and it is incompatible with pinning, which the provenance rules require. Related, and worth naming correctly: `cost_tier` is a BAND, not a ceiling (models CHEAPER than the tier are excluded too, and within the band ranking is still by market spend share); the actual ceiling is `max_price` in the provider object. Name the right field or make no cost claim.

**§VII.10 Pinning, and the provenance record for every probabilistic decision.** Production pins an exact version — `typesafe/jev-1.13`, never the rolling `~typesafe/jev-latest` (the tilde is part of the identifier; the vendor's own documentation says the alias moves). Adam is right to insist on this, and it is not sufficient: the independent evaluation tested `typesafe/jev-1.13-20260917`, a dated build served under the un-dated pinned name. **So record what the RESPONSE echoes, never what was sent.** Every probabilistic decision is banked in full or is not taken: model as requested; **resolved model id from the response**; **provider from the response** (on a gateway, a model id names what you asked for, not who ran it); gateway, endpoint and endpoint stability (an alpha endpoint is recorded as alpha); schema version; timestamp; **the verbatim question text and criteria** — criteria are load-bearing and drift silently, and wrong criteria descriptions have been measured driving accuracy to 16.7%, below a 25% random baseline, while merely missing ones cost 0.8 points; **the full option set presented, verbatim, with each option's source row**, without which MATCHING cannot later be told from COMPOSING; **the full probability vector**, not the argmax and not the winner's confidence alone, because calibration cannot be re-fitted from an argmax and re-fitting is not optional; the calibration artefact in force, its version, and the labelled set it was fitted on; input hash; output; `zdr` and `data_collection` as SENT and as REPORTED BACK; `session_id` if one was used, since it is a cross-request linking identifier and belongs in the record and not only in the code; cost and usage as returned, so every economic claim is re-derivable from the run that made it; and a **DISPOSITION** — what named human did what with the output, and when. Without disposition it is a log, not provenance. A confidence nobody can re-derive lands as a flagged candidate for a person and never as a silent edit.

**§VII.11 Rule 1 at the boundary — the closed-option gate, built before the first call.** A probability distribution over known senses is **MATCHING**, and permitted, if and only if every label is a BYTE-IDENTICAL string drawn from `hgm_gloss` or from Geshe Michael Roach's English in the landed corpus, each carrying the row it came from, and the model does nothing but distribute mass over them. It becomes **COMPOSING**, and forbidden, the moment any label is a paraphrase, a normalisation, a merge of two glosses, or a tidy-up written to make the option set read coherently — and a distribution over invented options is worse than plain composition, because it arrives wearing the costume of a measurement. The "unknown / new" option is the hinge. As a TERMINAL REFUSAL — none of the known senses apply, route to a human — it is mandatory, not merely safe: without an explicit none-of-these option, independent evaluation flagged ZERO of 30 out-of-scope inputs, all at high confidence. If it can ever be FILLED IN, by the model or by any downstream step that asks "so what is the new sense?", that is precisely the mechanism by which a machine would mint a new Geshe Michael Roach equivalent, and this repo has recorded that exact class twice. **The ruling, and it is buildable this week: a gate reads the option set BEFORE the call and refuses any label not found verbatim in `hgm_gloss` or the landed corpus — the same discipline `gen_alignment_page.py` already applies to spans against the spine — the option set is closed, and the unknown/new option is terminal and unexpandable by any automated step.** Prove the gate with a planted non-verbatim label, not with a passing example. Until it exists, whether an external classifier matches or composes is not answerable by inspection, only by trust.

**§VII.12 Data handling — and the question that is not the audit's to close.** **Whether corpus text may leave this machine at all is OPEN with Adam and the organisation.** ZDR is a retention promise, not a disclosure decision: sending Geshe Michael Roach's unpublished parallel corpus to a third party is an act of transmission whether or not anything is kept. Record it as OPEN in every report; do not let a configuration flag stand in for a ruling. The controls, with their carve-outs named: `provider.zdr: true` and `provider.data_collection: "deny"` are real request-level fields, OR'd with account and guardrail settings so a request cannot disable an enforced ZDR — but the vendor's own documentation states ZDR does NOT cover third-party plugins and tools, and that in-memory prompt caching is explicitly NOT classified as retention, which means the mechanism that makes a gateway attractive is the one ZDR carves out. The batch path — 50% off, and genuinely attractive for an overnight corpus job — stores inputs and results as JSONL in Google Cloud Storage for 30 days by default, does not cover the alpha Decisions endpoint, and has a shorter road: the provider's own Message Batches API is also 50%, with no gateway, no 5–5.5% fee and no third-party bucket in the path. Also note the linking surface the design itself introduces: `session_id` and `user` are cross-request correlation identifiers by design — the field that buys the cache hit is the field that stitches the requests together on the far side. **UNVERIFIED, and not to be carried forward as checked: that OpenRouter's provider directory lists TypeSafe as zero-retention.** The provider page is a directory listing carrying no data policy, no retention statement and no training statement; the authoritative inventory is the ZDR endpoint and its browsable filter, and somebody must read it and record what it said and on what date before one byte of corpus text is considered for that route. Operationally, any client this project writes must read `error.metadata.limit_source` on a 402 — the in-flight spending budget reserves estimated cost for concurrent requests and can fire with a positive balance, which is exactly a fan-out's shape — and must handle a 429 arriving AFTER a 200 as an SSE `finish_reason: "error"`, which a naive client silently records as a short completion.

Anything unmeasured is written UNVERIFIED in the ledger. A gateway may then be bought, or not — but it will have earned whichever it gets.
