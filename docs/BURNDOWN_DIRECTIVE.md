# THE BURNDOWN DIRECTIVE (Master Prompt 8 — an execution order, not a ring)
*(governs the /loop that finishes docs/CLOSER.md. No new vantage, no new
scope — those live in prompts 1–7. This directive tunes one thing:
THROUGHPUT.)*

1. **Every wave closes as many backlog items as fit** — not one. Items
   with no shared files may run through background agents in parallel;
   anything touching app/main.cpp stays serialized (the block-edit
   hazard is constitutional history).
2. **The gates are non-negotiable and already fast**: constitution +
   battery (60) at every commit; §11 visual gate and the three-gate
   press per announced batch; §10 adversarial review whenever behavior
   changed; new drills run twice.
3. **WAITING items are Adam's; the engine never idles on them.** Each
   wave's report re-states the waiting list verbatim-short. If every
   OPEN item is closed and only WAITING remain, the engine writes the
   RC letter (Closer §3) and stops the loop — that is the finish line.
4. **Reporting is burndown-first**: closed this wave · open · waiting ·
   deferred, then one line per closure with its proof.
5. **No prompt 9.** If new scope appears, it goes to the post-1.0
   roadmap. The next engine after this one is called "1.0.0".
