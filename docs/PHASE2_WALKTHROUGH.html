The tool, lived in: what the Phase-2 audit changed

A walkthrough letter for Adam — every claim below names the journey it improves and the way to see it with your own hands. 2026-08-20.

Phase 1 made the screens honest. Phase 2 asked a different question: what is this tool like to use — on a bad network, with a moved data folder, with a failing disk, at the keyboard, by a brand-new cataloger? We sabotaged it on purpose, sent an independent reviewer to refute our own fixes, and measured what had only been eyeballed. Here is what changed, journey by journey.

Your work, kept

Saving can no longer fail silently

Seven places could lose work while looking saved: alignment links (saved on every Space-bar press), glossary entries (the card showed the gloss from memory even when the disk write failed), typed transcription exports, OCR results, two export paths, and the catalog team roster. Each now warns in one consistent voice — the file, the reason, and the plain sentence “what you see on screen is NOT saved” — once per failing file, so an alignment session can never become a modal storm.

See it: Align pane → make the links folder read-only in Finder → draw a link. One warning, naming the file. Fix the folder; saving resumes silently.

The importer can no longer destroy what it replaces

Before: importing a data release deleted the old file first, then copied — a full disk or dropped network drive left you with neither. Now it stages the copy beside the target and swaps only on success; a failure leaves the working release untouched and says so.

Cold start

A missing data folder was a crash. Now it is a conversation.

Moving the app without its “ALL Tool Data” folder used to crash on launch — the old ask-a-folder dialog was masking an uncaught error behind it. Now a plain dialog explains what the data folder is and where it ships, lets you locate it (retrying on a wrong pick), and quits cleanly if you decline. We proved it with a scratch-machine rig: copied .app, empty home, no data — clean message, no crash.

The queue you rule on

The Approval pane, hardened by an adversary

An independent review agent attacked our own fixes and confirmed three real bugs, all now closed: a failed roster save during first set-up still signed you in as admin over a roster file that did not exist; a failed save could quietly un-revoke a revoked member; and two scriptable command-line modes could hang forever on a dialog nobody can click. The ruling links also now carry their consequence in color — ✓ approve commits, ✗ decline refuses, defer parks.

Reading

Measured ink, not eyeballed ink

We computed real WCAG contrast for every color on the card. The quiet grays failed — captions at 2.8:1, hints at 3.2:1 — and are now re-inked to pass, keeping their warmth. Gold text deepened for legibility while the chrome’s gold identity stays. Labels that sit on the theme-following chrome now measure their ink against the ground they actually sit on, light or dark. And inline Tibetan in the 84000 rows now honors a ruled floor of 16px — stacked glyphs never render at Latin body sizes anywhere on the card.

Finding things

From a search hit to the word’s card in one click

Before: copy the term, switch panes, paste, Return. Now the results footer offers “look up: …” for every searched term. And Help gained two sheets: Keyboard Shortcuts (the whole keyboard story in one place) and the Usage Ledger — an opt-in, this-Mac-only counter of pane visits and tool clicks whose single purpose is to let the ribbon and the manual be ordered by how you actually work instead of by guess.

See it: Research → Search → any term → Return → click its name in “look up:” under the total.
The gate

Every press now proves the screens still look right

The packaging script screenshots all 22 panes and compares them perceptually against a blessed baseline; unexplained change stops the press. The gate earned its keep before it ever guarded a release — it caught the screenshot harness itself being non-deterministic (the window grew mid-sweep and reflowed every later capture). Blessing a new baseline is an explicit act: tools/bless_shots.sh.
