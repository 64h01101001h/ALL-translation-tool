# Convert pane — release audit

## 1. Purpose and how it is reached

The Convert pane is the app's script- and notation-conversion surface: it wraps the battery-proven `allcore` engines for ACIP ⇄ EWTS wylie ⇄ Tibetan Unicode, the full Sanskrit notation set (IAST / Devanagari / Tibetanized ACIP / ACIP input-code / next-letter / IPA / simplified pronunciation), GMR-convention and THL phonetics, and the Tibetan calendar (Kālacakra karaṇa + Phugpa) colophon-date helper. It is built by the free function `makeConvertPane(allcore::Mvp*, allcore::WhitneyRoots*)` at `app/main.cpp:17588` and added to the main window's single top-level `QTabWidget` as the tab literally named **"Convert"** at `app/main.cpp:35987` (`tabs.addTab(makeConvertPane(mvp, whitney), "Convert");`), immediately after the Library / Files / Search tabs — the user reaches it by clicking that tab. `mvp` is an optional `allcore::Mvp` (Mahāvyutpatti DILA TEI table) loaded from `data/extracted/mahavyutpatti.tsv` at `app/main.cpp:35705-35710` and left `nullptr` if the file is missing; `whitney` is an optional `allcore::WhitneyRoots` (Whitney *Roots* 1885) loaded from `data/whitney/whitney_roots.tsv` at `app/main.cpp:35714-35719`, also `nullptr` when absent. Both are reference comparanda only; the pane has no buttons at all — every conversion is live-on-typing.

## 4. Dependencies

**Data files read** — none opened by the pane itself. It consumes two already-loaded optional tables built in `main()`:
- `data/extracted/mahavyutpatti.tsv` (via `allcore::Mvp`, main.cpp:35705-35710)
- `data/whitney/whitney_roots.tsv` (via `allcore::WhitneyRoots`, main.cpp:35714-35719)

Indirectly, `thlPhrase` calls through the global `g_segSylCounts` hook, which is wired to the Botok segmenter elsewhere in the app.

**Network hosts** — none. No `QNetworkAccessManager`, no URLs, no `QDesktopServices` in 17588–18239.

**Disk writes** — none. No `QFile`, `QDir`, `QProcess`, `QSettings`, or clipboard use in the range: the pane persists nothing, restores nothing, and has no context menu, shortcut, tooltip, or export path of its own.

**ctest suites validating the engines this pane calls** (names as registered in `core/CMakeLists.txt`): `engines_battery`, `forward_battery`, `towylie_battery`, `weird_battery`, `thl_battery`, `pron_standard_smoke`, `acipcodes_smoke`, `tibcal_smoke`, `tibcal_day_smoke`, `phugpa_smoke`, `mvp_smoke`, `whitney_smoke`.

## 5. Release questions

- **No pane-level self-test exists.** `grep selfTest` over 17588–18239 returns nothing, and the `--selftest` driver (main.cpp:38250-38300) calls `selfTest` on ~18 panes but never on Convert — it cannot, since `makeConvertPane` is a free function returning a bare `QWidget*`. Every Convert check in the driver (main.cpp:40267-40330) tests the *file-scope helpers* (`tiseWylieToUnicode`, `unicodeToWylie` round-trip, `thlPhrase`) rather than the widget. Should Convert be promoted to a class with a `selfTest`, given every other major pane has one?
- **Stale demo driver.** The screenshot harness at main.cpp:40895-40900 looks for a `QPushButton` whose text starts with "Convert" and clicks it. The pane has no buttons — conversion is live on `textChanged`. The click is a silent no-op; the demo only works by accident. Worth fixing or deleting so it cannot mask a regression.
- **Provisional / unvalidated directions that need a label or hiding:**
  - Tibetan-year → western-month-span is proven only for **2015–2035**; earlier years are computed by the same arithmetic and the caption says so, but the result is rendered in the same bold as proven output. Colophon years are, by definition, mostly outside the proven window — this is the pane's most likely source of a wrong published date.
  - The karaṇa `YYYY mN` month table is the *non*-almanac system; published almanacs use Phugpa and differ by a whole month in leap-affected years. The warning is in small text under the table.
  - Sanskrit **simplified pronunciation** is flagged provisional in CLAUDE.md ("pending the separate ACIP pronunciation standards doc") but the card presents it as following "the ACIP pronunciation standard". Reconcile the label with the project's own status.
  - `iastToInputcode` / `iastToNextletter` / `iastToPronunciation` / `sanskritLetterGuide` return no success flag, so those four rows can never show `⟨…⟩`. That is a gap in the "flagged, never guessed" guarantee the banner makes.
- **The ACIP-vs-wylie detector is a 60%-uppercase heuristic** (main.cpp:18160) with no user override and no indication that a guess was made beyond the "detected" row. Should the pane offer an explicit input-notation selector?
- **Performance:** the converter reruns on every keystroke over the entire buffer, including Mvp and Whitney lookups. No debounce, no length cap. Confirm behaviour on a pasted page-length passage before release.
- **UI claims hard numbers** ("proven 100.000% on 109,490 fixtures", "76/76 verified against Henning's original", "proven 21 oracle years", "proven 26 years"). These are baked into strings with no link to the suites that establish them; a battery regression would leave the claims standing. Consider gating or sourcing them.
