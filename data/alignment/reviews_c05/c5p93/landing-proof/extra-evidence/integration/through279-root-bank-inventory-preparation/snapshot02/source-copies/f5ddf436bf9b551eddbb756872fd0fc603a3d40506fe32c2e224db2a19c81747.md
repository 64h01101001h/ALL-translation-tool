This is the proposed `reconciliation-277-v1` interface. `config_contract.py` is its strict executable validator, and `completed-277-config.json` is an actual completed-batch fixture, not a future-batch template with invented values. All JSON inputs retain their original full bytes. Parsing does not normalize source strings, SQL, parameters, embedded raw JSON strings or output bytes.

Every file reference is exactly `{path, bytes, sha256}`: an absolute existing file, nonnegative integer length and lowercase SHA256. Runtime checks full bytes, not a hash-only substitute for source reading. Config itself is pinned by the explicit command argument. The caller must supply reviewed provenance and the actual operator role; pins do not establish authorship or semantic correctness.

Top-level keys are exactly schema, course, batch, worktree, shared_directory, sequences, baseline, status_capture, originals, reconciled, evidence, context, query_directories, queries, operator_role. The course is Cnn; exactly three positive, consecutive, ordered sequences identify the batch basename. Baseline is the actual pinned baseline.json, its boundary immediately precedes the first sequence, and its commit and complete source hash map remain runtime gates. Status_capture is a pinned actual prior full raw `git status --short` stream with its command/history retained separately; it is checked before and after runtime. It is historical expectation, never fresh MAIN clearance.

Originals are exactly Tibetan then English, all three segments in order. Every record has angle, seq, directory, freeze, spec and declarations. Freeze/spec/declaration references must belong to the exact angle/sequence directory and match the pinned freeze. Original span counts derive from every full spec; every unique angle/seq/id must occur exactly once in the pinned root-original identity file, with the complete original span object, original key order and id/depth/Tibetan/English fields equal. The separately pinned original verification proof must be PASS and identify those exact six freezes. This remains a required prior six-original verification interface; this candidate does not replace that independent actual original verification with a count check. Runtime retains all original occurrence declarations, parents, optional field-presence, identities and dispositions checks against that fully bound root-original file.

Reconciled records have exactly seq, directory, freeze, counts and files. Counts contain spans, nulls and d5_nonnull, all measured from the complete spec and equal to the actual pinned per-segment proof's reported counts. No expected original or final total is an executable constant. Files explicitly bind spec, body, tuples, decisions, omissions, dispositions, errata_analysis, allowances, errata and proof to their current exact filenames and matching freeze entries. The complete nine original/reconciled directories are still enumerated and every file fully checked before and after runtime, including nested historical freezes and failed attempts.

Evidence roles are exactly reference_access, copy_manifest, aliases, governing, source_context, physical, original_identities, original_proof, source_snapshot, master, corpus, database, generator and wrapper. Current schema pins the actual hgm_spine_v27_2.db, hgm_dictionary_v27_2.json.gz, full_parallel_corpus_v32.json.gz and gen_alignment_page.py locations within the specified worktree. The wrapper must be in the specified shared evidence directory. Raw archives/database get full initial and final runtime byte pin checks; pure config helper tests intentionally do not repeatedly reread them. The preparation proof separately measured their full bytes once. All original/copy pairs still require full byte equality, aliases retain actual resolved and symlink identities, and governing Git objects require the actual baseline commit/path/argv/cwd/exit and reproduced full bytes.

Context has the exact current full-row SELECT text and explicit [course, first, last] parameters. It must include all three segments, and pinned context rows must cover the complete consecutive interval. Runtime reopens URI mode=ro SQLite, enables/verifies query_only, starts a read transaction, reproduces every full row and compares all raw objects against the complete decompressed original archives. It checks the six current source fields exactly and preserves the complete query outputs.

Query directories are explicit, unique and inside the shared evidence directory. The query list is their exact complete *.json union, with no duplicate paths. Each record is exactly file, descriptor and binding; the descriptor must be an actual original recorded by the full pinned original-copy manifest. Three genuine descriptor shapes are supported: standalone full query; zero-based index in a full query list; or the English HGM results map using exactly parameters_per_term `[term,term]` and its actual term. Missing count is accepted only when absent from that selected genuine original descriptor. Added/removed count, changed SQL/parameters/full rows/raw string, unsupported parameter construction or unknown binding keys reject. There is no numeric filename exemption or general allow_missing_count switch.

The runtime's final canonical execution remains once per configured final segment, through the exact pinned read-only wrapper and actual unchanged generator. Actual command, stdin/stdout/stderr/exit are saved; nonzero exit or any stderr fails. Saved bodies must be byte-identical. Removing exactly the counted null markup for the source-anchor comparison retains correction02's narrow rule; the original HTML body remains untouched. Complete ordered seven-key tuples, current span objects/rationales, every original disposition/declaration/parent/optional key, every intended range and full unwrapped complement remain checked. All errata must remain refuted with five grounds and errata.json empty; allowances and actual gated hits must remain empty. This strict current schema deliberately does not generalize nonempty errata/allowances or alternate declaration layouts: those need a separately reviewed adaptation.

Execution requires separate review of both code files, config and actual inputs, a new external output directory and `--execute-reviewed-verification`. The flag is an operator assertion, not evidence of authorization. The CLI rejects optimized Python explicitly before configuration reads; all other assertion gates remain enabled. No routine here approves semantics, lands data, runs page builders, changes indexes, commits, or certifies a new baseline. Runtime executes read-only Git and SQL plus the pinned canonical wrapper; approval must establish the actual safety of those pinned sources. Preparation never calls the full verifier, SQL, Git or canonical producer.

Failure contract: retain caller argv/cwd/environment/start/end, full stdout/stderr/exit and all partial fresh output even for config preflight failure before directory creation. Once runtime begins, execution-proof.json records failure and completed command outputs survive; do not overwrite a failed directory. Stop on any changed input or schema mismatch. Independent source inspection, semantic review, actual original verification, canonical gates and all other campaign acceptance checks remain separate and mandatory.
